# 递归 AGENTS.md 文档体系 - 完整设计

> 本文档为 River 广告平台 AI Agent 开发规范的递归文档体系设计。
> 
> **设计原则**：使用模式+约定，避免硬编码，使文档易于维护和扩展。

---

## 1. 目录结构设计

### 1.1 模式定义

```
project-root/
├── AGENTS.md                              # 项目级通用规范 + 子项目索引
├── {subproject-name}/                     # 子项目目录
│   ├── AGENTS.md                          # 继承通用规范 + 子项目特有规范
│   └── src/                               # 源代码目录
└── ...                                    # 更多子项目
```

### 1.2 当前项目应用

| 角色 | 目录 | 描述 |
|------|------|------|
| 项目根目录 | `river-ad-workspace/` | 包含所有子项目 |
| 子项目 A | `river-server/` | 后端服务（Java 技术栈） |
| 子项目 B | `river-ui-admin/` | 管理后台（Vue3 技术栈） |
| 子项目 C | `river-ecommica/` | 前端站点（Next.js 技术栈） |

## 2. 文档继承机制

### 2.1 继承模式

```
┌─────────────────────────────────────────────────────────────┐
│  project-root/AGENTS.md                                     │
│  ├── 通用规范（适用于所有子项目）                            │
│  ├── 子项目索引（相对路径引用）                              │
│  └── 跨项目约定                                              │
└─────────────────────────────────────────────────────────────┘
                            ↓ 继承
┌─────────────────────────────────────────────────────────────┐
│  {subproject}/AGENTS.md                                     │
│  ├── 继承声明（引用 project-root/AGENTS.md）                 │
│  ├── 子项目特有规范（不通用内容）                            │
│  └── 可复用功能清单                                          │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 继承声明模板

> 每个子项目的 AGENTS.md 开头应包含继承声明：

```markdown
# {子项目名} - AI Agent 开发规范

> 本文档继承自 [项目通用规范](../AGENTS.md)。
> 
> 如未特别说明，遵循项目通用规范的所有约定。

## 特有规范

本文档记录以下 **不通用** 的规范：
- 技术栈特定约定
- 项目结构约定
- 禁止重复造轮子的清单
```

## 3. 通用规范（project-root/AGENTS.md）

### 3.1 Git 使用约定

| 约定 | 模式 | 说明 |
|------|------|------|
| 提交规则 | 禁止主动提交 | 除非用户明确要求，否则不创建 Git 提交 |
| 删除规则 | 软删除优先 | 数据记录使用 `deleted` 字段标记，非物理删除 |
| 变更模式 | 遵循现有模式 | 创建新代码前先查看类似模块的风格 |

### 3.2 数据库约定

| 约定 | 模式 | 说明 |
|------|------|------|
| 多租户 | 租户字段必选 | 所有业务表包含 `tenant_id` 字段 |
| 表命名 | 前缀分类 | 新业务模块使用项目前缀，框架模块使用系统前缀 |

### 3.3 子项目索引

> 子项目 AGENTS.md 通过相对路径引用：

| 子项目 | AGENTS.md 路径 | 技术栈分类 |
|--------|----------------|-----------|
| 后端服务 | `river-server/AGENTS.md` | Java 后端 |
| 管理后台 | `river-ui-admin/AGENTS.md` | Vue3 前端 |
| 前端站点 | `river-ecommica/AGENTS.md` | Next.js 前端 |

#### 4.1.2 模块命名模式

| 模式 | 示例 | 说明 |
|------|------|------|
| 框架模块 | `river-framework/*` | 提供基础设施功能 |
| 业务模块 | `river-module-*` | 提供业务功能 |
| 服务模块 | `river-server` | 主启动模块 |

#### 4.1.3 框架 Starter 分类

> **避免硬编码**：使用分类模式描述，而非列出所有具体模块名。

| 分类 | 功能模式 | 依赖模式 | 继承关系 |
|------|----------|----------|----------|
| 基础设施 | 数据库访问 | starter-mybatis 类型 | 依赖 common |
| 基础设施 | 缓存操作 | starter-redis 类型 | 依赖 common |
| 基础设施 | Web 功能 | starter-web 类型 | 依赖 common |
| 安全认证 | 权限校验 | starter-security 类型 | 依赖 web |
| 服务保障 | 分布式锁 | starter-protection 类型 | 依赖 web + redis |
| 任务调度 | 定时/异步 | starter-job 类型 | 依赖 common |
| 消息通信 | 消息队列 | starter-mq 类型 | 依赖 redis |
| 业务增强 | 多租户/数据权限 | starter-biz-* 类型 | 依赖 security |

#### 4.1.4 业务模块分类

| 分类 | 模式 | 说明 |
|------|------|------|
| 系统模块 | system 类型 | 用户、角色、菜单、权限 |
| 基础设施 | infra 类型 | 代码生成、配置、定时任务、文件 |
| 业务模块 | affiliate/tracking/coupon/blog/campaign/stats | 核心业务功能 |

#### 4.1.5 代码结构模式

```
{service-package}/
├── api/                    # 服务接口定义（跨模块调用）
├── controller/             # REST 控制器（按访问入口分类）
├── convert/                # 对象转换（MapStruct）
├── dal/                    # 数据访问层
│   ├── dataobject/         # 数据对象（DO）
│   └── mysql/              # MyBatis Mapper
├── enums/                  # 枚举定义
├── framework/              # 模块配置
└── service/                # 业务逻辑层
```

#### 4.1.6 测试基类模式

| 测试类型 | 基类模式 | 依赖模式 | 说明 |
|----------|----------|----------|------|
| 纯单元测试 | BaseMockitoUnitTest | starter-test 类型 | 无数据库依赖 |
| 数据库测试 | BaseDbUnitTest | starter-test 类型 + mybatis | 需要 DBUnit |
| 缓存测试 | BaseRedisUnitTest | starter-test 类型 + redis | 需要 Redis |

## 6. 维护指南

### 6.1 添加新模块

当添加新的业务模块时：

1. **确定模块类型**：框架模块 / 业务模块
2. **遵循命名模式**：使用项目约定的前缀
3. **更新分类清单**：在对应 AGENTS.md 中添加分类条目
4. **更新禁止清单**：如需禁止重复造轮子，添加功能模式条目

### 6.2 更新框架版本

当框架升级带来新功能时：

1. **更新分类清单**：添加新功能分类
2. **更新禁止清单**：如新增禁止项，添加功能模式条目
3. **保持模式描述**：避免硬编码具体版本号

### 6.3 添加新子项目

当添加新的子项目时：

1. **创建 AGENTS.md**：使用继承声明模板
2. **添加特有规范**：记录子项目特有的规范
3. **更新根目录索引**：在 AGENTS.md 中添加子项目索引

## 7. 规范使用示例

### 7.1 AI Agent 开发流程

```
Step 1: 读取 project-root/AGENTS.md
        ↓ 了解通用规范
Step 2: 进入对应子项目目录
        ↓ 读取 {subproject}/AGENTS.md
Step 3: 遵循子项目特有规范
        ↓ 开发
Step 4: 提交前检查
        - 是否遵循禁止重复造轮子清单？
        - 是否遵循代码结构模式？
```

### 7.2 遇到问题时的处理

| 问题类型 | 处理模式 |
|----------|----------|
| 通用规范问题 | 查看 project-root/AGENTS.md |
| 子项目特有规范问题 | 查看对应子项目的 AGENTS.md |
| 框架功能问题 | 查看对应子项目的「可复用功能清单」 |
| 重复造轮子问题 | 查看对应子项目的「禁止重复造轮子清单」 |
